# Claims: every number stated in this repository, with the command that reproduces it

One table. Each row: the claim in one sentence, the command that reproduces it, the value to expect, the allowed difference,
and how long the command takes. Every number in every page of this repository is a row here, or is marked in its page as a
number from the project's record that no committed command reproduces (those are rows too, in the last part of the table,
with "no committed command" in the command column).

How to read the table:

- `PY` stands for `python -I -B -X utf8`. Every command is run from the repository's top, after the setup page
  (`README.md` in this folder) has been followed: `settings.cfg` filled in, and for the compiled rows `make` run in
  `3-compiled-solution` on the Linux side.
- "check.py line ..." means: run `PY 2-python-solution/check.py` (with `--slow` for the slow rows) or
  `PY 3-compiled-solution/check.py`, and read the line that begins with the quoted words. Each line prints the difference
  found and the limit; the row's "expect" is the difference found on the machine this was written on, and "allowed" is the
  limit the check applies. A reader on another machine should see the same digits for the deterministic values and the
  same order of magnitude for the differences.
- Values and differences are deterministic: the same inputs give the same digits on this machine, and digits may differ in
  the last places on another processor or NumPy. Times are not deterministic: the allowed difference for a time is the
  scatter seen in repeated runs here, ±20% for Python and ±10% compiled, and a different processor gives different times.
- The times were measured on one core of a laptop (Intel Core Ultra 7 258V, Windows 11; the compiled program on Ubuntu 24.04
  under WSL on the same machine), with nothing else of ours running. Two dates are given for each time: the project's
  measurements of 22 November 2026, which the other pages quote (3.2 and 0.4 thousandths of a second), and a repeat on
  23 November 2026 with the same commands, on which every program, Python and compiled alike, ran 1.5 to 2.5 times slower
  while giving the same numbers to the last digit. The cause lies in the machine's state, not in the programs (no program
  changed between the two days); the one difference found is that on 23 November the laptop was running on its battery
  (73% charged, as Windows reported it). That was the cause: later the same day, on mains power, the same commands gave
  the figures of 22 November again (row F8). Whoever repeats a time on a laptop should check which of the two it is on,
  and a different processor gives different times again.
- Rows A3, A4, I and J speak of threads (lines of work of one program, each on a processor core, running at the same
  moment), OpenMP (a feature of the compiler that shares the turns of a loop among threads) and a race (two threads
  touching the same memory with nothing to put one before the other), which the race detector watches for.
- The public code X-PSI's time on this machine was measured on 23 November 2026, with X-PSI (version 3.5.0b1, at the
  commit the setup page names) installed in its own folder on the Linux side of the same laptop: group H. Every row whose
  command needs X-PSI installed says "needs X-PSI" (the setup page, section 6, says how to install and run it). In those
  rows `CMP times` stands for
  `PY 2-python-solution/tools/compare_with_public_code.py 2-python-solution/results/public_code_times.jsonl "<power state>"`,
  run after `bash 2-python-solution/tools/run_public_code_timing.sh`, and `CMP refine` for the same with
  `public_code_refine.jsonl`, run after `bash 2-python-solution/tools/refine_public_code.sh`; what they printed on
  23 November is in `measured-2026-11-23/` (its `README.md` names each file). Speed ratios against X-PSI are stated only
  for the quick example at X-PSI's shipped settings, with the power state and the accuracy of each program beside them
  (H5 to H7). X-PSI's times were taken once on each power state, so no scatter is known for them.
